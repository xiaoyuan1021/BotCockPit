# BotCockpit 四周计划

- **周期**：约 1 个月（可按周顺延）  
- **协作**：AI 实现；本人负责需求边界、协议评审、验收与面试表述  
- **主路径**：仿真假车，不依赖实车  
- **产品名**：BotCockpit — ROS2 机器人调试上位机（QML）

---

## 成功标准（月底必须成立）

1. 一键启动：`fake_robot` + `botcockpit_bridge`，QML 可连接  
2. 实时状态：节点健康、模式/相位、心跳 RTT 可见且刷新正常  
3. 控制闭环：任务下发有 ACK；软急停立即生效；故障可复位（二次确认）  
4. 故障路径：杀节点 / 断网 → 系统进入安全态，UI 有明确指示  
5. 工程交付：`PROTOCOL.md` 与实现一致；README 3 分钟可跑通；有演示 GIF  
6. 测试：`tools/fake_client.py` 冒烟 + 至少 3 条 launch_testing（第 2 周起）

## 第 2 周 — 控得住、故障可测

**目标**：状态机 + 指令通道 + 安全策略可被自动化验证。

| 任务 | 产出 |
|------|------|
| 2.1 机器人侧状态机 | `BOOT → INIT → IDLE ⇄ RUNNING → FAULT/DEGRADED`，`ESTOP` 最高优先 |
| 2.2 指令闭环 | `CMD_MODE` / `CMD_TASK` / `CMD_ESTOP` / `CMD_RESET` + ACK/NACK |
| 2.3 安全策略 | 心跳超时 / 关键节点挂 → 禁止新任务并 SAFE 停止 |
| 2.4 QML Control 页 | 模式、任务、软急停、复位（二次确认） |
| 2.5 launch_testing | ≥3 条：正常任务、断线安全、急停锁定 |
| 2.6 故障注入工具 | `tools/inject_fault` 脚本或 ROS service |

**验收**  
- 断 bridge 或假车后 3s 内系统相位/控制使能正确  
- ESTOP 后拒绝 AUTO 任务直至复位成功  
- launch_testing 全绿

## 简历项目描述（定稿口径）

**BotCockpit — ROS2 机器人调试上位机**  
技术栈：Qt6 Quick/QML，C++，TCP，ROS2，CMake  

- 开发面向 ROS2 机器人的桌面调试工具：节点/诊断监控、任务下发、软急停与故障复位；  
- 设计 TCP 心跳与指令 ACK 协议，C++ 后端解耦 QML 界面，支持断线重连与安全停止；  
- QML 实现连接、总览、控制、故障四页工作流，面向实验室联调与仿真场景。  

（若完成测试）补充：  
- 桥接层故障注入与 launch_testing，验证断线与急停场景下的安全态。

## AI 协作约束（每张任务卡都附上）

```text
项目：BotCockpit（docs/PROTOCOL.md 为准，禁止擅自改协议语义）
角色：你实现，用户验收
约束：
- 只做当前任务卡范围，一次一个模块
- 必须可编译/可运行，并写 3 步手动验证
- QML 不写协议业务；网络与编解码在 C++
- C++ 优先；工具脚本可用 Python
禁止：
- 引入公司代码/UI 资源
- 无关重构、一次性大爆炸提交
- 在验收未通过时增加新功能
```
